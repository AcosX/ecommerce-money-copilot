# 小商工具的数据完整性（#88、#89、#90）

## 费用验算

费用按完整标签顺序解析，同一个金额只归属一个标签。`快递包材8` 是一笔合计，
`运费成本8、包材成本2` 是两笔费用，不会覆盖拿货成本。同一标签多次出现时使用
最后一次修正值；佣金最后一次的百分号决定按比例还是按元计费。综合成本不再另加明细。

组合费用和独立运费/包材同时出现时不自动相加，聊天请求先确认是否重叠。
结果只称“按已知成本的每单差额”，缺失广告费、税费、退货损耗仍提示待补充。

## 草稿保存

- 保存指令本身不是方案。没有正文、同项目同关卡的已生成方案或现有草稿时，
  返回需要补充正文，不产生占位版本。
- `保存草稿：正文` 保存冒号后的原文；`save_as_draft` 也接受实际用户正文。
- 实时模型生成的方案在生成完成后保存；生成服务不可用时不冒充生成成功。
  后续“保存刚才的方案”只使用服务端记录、相同会话/项目/关卡的方案正文。
- 更新同项目、同成果类型的 draft/rejected 时，传入字段覆盖同名字段，未传字段保留。
  正文、预算和证据分组因此不会被仅含保存指令的元数据替换。历史 revision 只追加。
- 不提供 content 的直接保存工具调用返回 422。项目仍按当前登录玩家验证归属。

## 认证反馈范围

聊天和 `get_review_feedback` 工具均从 `client_context.active_project.id` 解析项目，
并验证归属；没有显式选择时，使用服务端解析的默认项目。查询关联成果，
同时过滤申请与成果的玩家归属、成果项目。项目无申请时返回 `found: false`，
不回退到同账号其他项目。相同项目按申请时间、ID倒序选择最新记录。

显式 `submission_id` 也必须属于当前项目，否则返回 404。要查询其他项目的申请，
应先选择那个项目；跨玩家项目和申请始终不可读取。

## 验证

`backend/tests/test_agent_integrity.py` 使用隔离的真实 MariaDB 测试库和 HTTP 入口，
覆盖原始金额复现、费用修正/歧义、草稿正文与历史版本、生成失败、保存开关、
项目切换、项目内多次申请及跨玩家拒绝。上游模型用受控响应替代，不依赖生产数据。
